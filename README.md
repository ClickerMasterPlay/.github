## Resource Magnate — Техническое описание Backend (MVP)

### Что это за система

Клиент-серверная idle-игра.  
Клиент (React) только показывает интерфейс и отправляет действия.  
**Вся логика, прогресс, деньги и рейтинг живут на сервере.**

Игрок:
- кликает по блокам → получает ресурсы и валюту
- покупает улучшения, инструменты и машины
- машины работают даже когда он оффлайн
- может играть гостем, потом зарегистрироваться и сохранить прогресс
- видит свой профиль и место в глобальном рейтинге

---

### Основные сущности (что храним в базе)

| Сущность | Что это |
|---------|--------|
| **User** | Игрок (гость или зарегистрированный). У гостя есть UUID, у зарегистрированного — email/пароль + тот же UUID. |
| **Progress / Save** | Текущее состояние игрока: валюта, ресурсы, надетый инструмент, установленные машины, сила клика и т.д. |
| **Block** | Тип блока (обычный, железный, золотой...). Имеет прочность, редкость и награду. |
| **Tool** | Инструмент. Влияет на скорость разрушения и выход ресурса. |
| **Machine** | Машина автодобычи. Имеет производительность и время последней фиксации. |
| **Inventory** | Что есть у игрока: ресурсы, инструменты, машины. |
| **Purchase** | Запись о покупке (для идемпотентности). |
| **Leaderboard** | Позиция игрока в рейтинге (можно считать по валюте / общему прогрессу). |

---

### Что должен уметь Backend (минимальный набор)

#### 1. Пользователи и гостевой режим
- Создать гостевую сессию (получить UUID)
- Зарегистрировать аккаунт и **перенести** гостевой прогресс
- Войти в аккаунт

#### 2. Добыча (клики)
- Клиент собирает клики и раз в несколько секунд отправляет **пакет**
- Сервер проверяет:
  - не слишком ли часто приходят клики
  - какой блок сейчас
  - какой инструмент надет
- Начисляет ресурсы и валюту
- Уменьшает прочность блока (или выдаёт новый)

#### 3. Магазин и покупки
- Купить улучшение клика
- Купить инструмент
- Купить машину
- Покупка должна быть **идемпотентной** (повторный запрос с тем же ключом не списывает деньги дважды)
- Всё в одной транзакции: списать валюту + выдать предмет

#### 4. Автодобыча (оффлайн)
- При входе в игру сервер считает, сколько времени прошло с последнего захода
- Начисляет ресурсы с установленных машин (с ограничением по максимальному окну, например 12–24 часа)

#### 5. Инвентарь и профиль
- Отдать текущий инвентарь
- Отдать профиль (валюта, ресурсы, статистика)

#### 6. Рейтинг
- Отдать таблицу лидеров
- Показать место текущего игрока

### Порядок разработки 

**Этап 0 — Каркас**
1. Создать Spring Boot проект
2. Поднять PostgreSQL + Redis через docker-compose
3. Настроить Flyway
4. Сделать простой health-check (`/actuator/health`)

**Этап 1 — Пользователи**
- Создать гостя → получить `userId` (UUID)
- Сохранить пустой прогресс
- Регистрация + перенос прогресса

**Этап 2 — Экономика и инвентарь**
- Модель баланса (валюта + ресурсы)
- Модель инвентаря
- Эндпоинт «получить мой прогресс»

**Этап 3 — Клики**
- Приём пакета кликов
- Валидация темпа (через Redis)
- Начисление награды
- Обновление прочности блока

**Этап 4 — Магазин**
- Список товаров
- Покупка с проверкой баланса
- Идемпотентность по ключу
- Транзакция

**Этап 5 — Машины и оффлайн**
- Установка машины
- Расчёт начисления при входе

**Этап 6 — Рейтинг**
- Простая таблица по валюте или общему прогрессу
- Кэш в Redis

### Важные технические решения 

1. **Источник истины — сервер**  
   Клиент никогда сам не меняет баланс. Он только просит, сервер решает.

2. **Пакеты кликов**  
   Клиент не шлёт каждый клик. Шлёт раз в 2–5 секунд пачку. Сервер проверяет разумность количества.

3. **Идемпотентность покупок**  
   Клиент при покупке присылает `Idempotency-Key` (UUID). Сервер запоминает его и при повторе возвращает тот же результат.

4. **Транзакции**  
   Списание валюты + выдача предмета — всегда в одной `@Transactional` операции.

5. **Оффлайн-начисление**  
   Считается по формуле:  
   `добыча = производительность_машины × min(прошедшее_время, max_window)`

6. **Rate limiting**  
   Ограничение частоты запросов (особенно кликов) лучше делать через Redis.

---

### Что можно сделать прямо сейчас

1. Создать репозиторий
2. Сгенерировать Spring Boot проект (start.spring.io):
   - Spring Web
   - Spring Data JPA
   - PostgreSQL Driver
   - Lombok
   - Validation
   - Spring Data Redis
3. Написать `docker-compose.yml` с PostgreSQL и Redis
4. Сделать первую сущность `User` и эндпоинт создания гостя
5. Сохранить прогресс в БД

## 2. Дизайн-система (минимальный набор для старта)

### Редкость (обязательно цветовая кодировка)

| Редкость | Цвет (пример) | Где используется |
|---------|---------------|------------------|
| Обычный | Серый / белый | Блоки, предметы |
| Необычный | Зелёный | Блоки, инструменты |
| Редкий | Синий | Блоки, инструменты, машины |
| Эпический | Фиолетовый | Инструменты, машины |
| Легендарный | Оранжевый / золотой | Топ-предметы |

### Основные компоненты, которые нужно сразу заложить

- Карточка предмета (иконка + название + редкость + цена / статус)
- Полоска прочности блока
- Кнопка покупки с состояниями:
  - Можно купить
  - Не хватает валюты
  - Уже куплено / уже есть
- Бейдж «Гость»
- Тост / уведомление о награде
- Пустое состояние (пустой инвентарь, нет машин и т.д.)
- Скелетон / лоадер

## 3. Экран «Добыча» (главный игровой экран)

**Ответственная:** Владислава

### Цель экрана
Игрок кликает по блоку, видит прочность, получает ресурсы и валюту, понимает, какой инструмент надет и какая сила клика.

### Основные элементы

1. **Центральный блок**
   - Большой визуал блока (зависит от редкости)
   - Полоска прочности (HP)
   - Под блоком: название + редкость
   - Превью награды (сколько ресурсов и валюты упадёт)

2. **Информация о клике**
   - Надетый инструмент (иконка + название)
   - Сила клика (число)
   - Кнопка/зона клика (весь блок кликабелен)

3. **Лента наград** (справа или снизу)
   - Последние полученные ресурсы/валюта (с анимацией появления)

4. **Краткая сводка**
   - Текущая валюта (дублирует шапку)
   - Основные ресурсы

### Состояния экрана

| Состояние | Что показывать |
|----------|----------------|
| Обычная игра | Блок + прочность + инструмент |
| Блок разрушен | Короткая анимация + новый блок |
| Нет сети | Блок заблокирован + сообщение «Нет соединения» |
| Первый вход | Подсказка «Кликай по блоку» |

### Данные, которые будут приходить с бэкенда
- Текущий блок (тип, редкость, текущая/максимальная прочность)
- Надетый инструмент
- Сила клика
- Баланс валюты и ресурсов
- Последние награды (опционально)

---

## 4. Экран «Магазин»

**Ответственная:** Владислава

### Цель
Покупка улучшений клика, инструментов и машин автодобычи.

### Структура

Три категории (табы или секции):

1. **Улучшения клика**
2. **Инструменты**
3. **Машины**

### Карточка товара (единый компонент)

- Иконка
- Название
- Редкость (цвет)
- Описание эффекта (коротко)
- Цена
- Кнопка действия

### Состояния кнопки покупки

| Состояние | Вид кнопки |
|----------|------------|
| Можно купить | Активная, «Купить» |
| Не хватает валюты | Неактивная, «Недостаточно» |
| Уже куплено / уже есть | «Куплено» или «В инвентаре» |
| Идёт покупка | Лоадер на кнопке |

### Важные моменты
- После успешной покупки валюта в шапке должна обновляться сразу (оптимистично + подтверждение с сервера).
- При ошибке — тост с причиной.

---

## 5. Экран «Инвентарь»

**Ответственная:** Виктория

### Цель
Показать всё, что есть у игрока, и дать надеть инструмент / установить машину.

### Секции

1. **Ресурсы**  
   Список ресурсов с количеством.

2. **Инструменты**  
   - Список инструментов
   - Отметка «Надет»
   - Кнопка «Надеть»

3. **Машины**
   - Машины на складе
   - Установленные машины (отдельно)
   - Кнопка «Установить» / «Снять»

### Состояния
- Пустой инвентарь → красивая заглушка
- Машина установлена → видно, сколько примерно даёт в час

---

## 6. Экран «Профиль»

**Ответственная:** Виктория

### Что показывать

- Статус: Гость / Аккаунт
- Если гость — большой баннер «Зарегистрируйся, чтобы не потерять прогресс» + кнопки «Войти» / «Создать аккаунт»
- Основные показатели:
  - Всего разрушено блоков
  - Всего добыто ресурсов
  - Текущий капитал (валюта)
  - Сила клика
  - Количество машин
- Кнопка выхода (если аккаунт)

### Особые сценарии
- После регистрации гостевой прогресс должен остаться (это критично).
- После входа — данные обновляются.

---

## 7. Экран «Рейтинг»

**Ответственная:** Виктория

### Содержание

- Таблица лидеров (место, ник / «Гость», очки)
- Текущий игрок всегда подсвечен и виден (даже если он далеко)
- Можно сделать топ-100 + строка «Ваше место: N»

### Состояния
- Загрузка
- Ошибка загрузки
- Игрок не в топе → всё равно показывать его позицию

## 8. Глобальные UI-состояния (обязательно учесть)

| Ситуация | Поведение |
|---------|----------|
| Нет интернета | Все действия, меняющие прогресс, блокируются. Показывается баннер. |
| Сервер думает (покупка, пакет кликов) | Кнопки в состоянии loading |
| Успешное действие | Тост или анимация награды |
| Ошибка | Тост с понятным текстом |
| Гость | Везде виден бейдж «Гость» |

# Общее правило разделения

| Зона | Кто отвечает | Почему |
|------|--------------|--------|
| **Аккаунты, экономика, покупки, целостность данных** | **Дима** | деньги, идемпотентность, перенос прогресса |
| **Добыча, клики, машины, рейтинг, инфраструктура** | **Егор** | Высокая частота событий + инфраструктура |
| **Архитектура, ревью, мерж, оценка задач** | **Дима** (как тимлид) | — |
